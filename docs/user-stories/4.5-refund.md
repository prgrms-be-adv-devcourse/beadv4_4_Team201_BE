# 4.5 결제 취소 및 환불 (Refund)

## 설명
펀딩이 실패한 경우, 참여자의 결제 금액은 자동으로 환불된다.

## User Story

> *"펀딩이 실패하면 내가 결제한 금액을 자동으로 돌려받고 싶다."*

## Acceptance Criteria

```gherkin
Feature: 펀딩 만료 시 자동 환불

🔹Scenario: 펀딩 만료로 인한 환불 처리
  Given 사용자가 펀딩에 20,000원을 결제한 상태이다
  And 해당 Funding의 상태가 IN_PROGRESS이다
  And 해당 Funding의 deadline이 현재 시간보다 이전이다
  When FundingScheduler가 expireExpiredFundings()를 실행하면
  Then 1. FundingExpireUseCase가 만료된 펀딩을 조회한다
  And 2. Funding.expire(now)가 호출되어 상태가 EXPIRED로 변경된다
  And 3. FundingExpiredEvent가 발행된다
  And 4. OrderEventListener.on(FundingExpiredEvent)가 이벤트를 수신한다
  And 5. FundingOrderService.requestCancelFundingOrder()가 호출된다
  And 6. CancelPaymentService.cancel()이 호출된다
  And 7. TossPaymentsGatewayAdapter를 통해 PG 취소 API가 호출된다
  And 8. 환불 성공 시 Payment 상태가 CANCELED로 변경된다
  And 9. Cancel 엔티티가 생성되어 취소 내역이 기록된다
  And 10. PaymentCanceledEvent가 발행된다

🔹Scenario: 펀딩 거절로 인한 환불 처리
  Given 사용자가 펀딩에 20,000원을 결제한 상태이다
  And 해당 Funding의 상태가 ACHIEVED이다 (목표 달성)
  When 수령자가 POST /api/v2/fundings/{id}/refuse를 호출하면
  Then 1. FundingRefuseUseCase.refuseFunding()이 호출된다
  And 2. Funding.refuse()가 호출되어 상태가 REFUSED로 변경된다
  And 3. FundingCanceledEvent가 발행된다
  And 4. OrderEventListener.on(FundingCanceledEvent)가 이벤트를 수신한다
  And 5. 이후 환불 플로우는 만료 시나리오와 동일하게 진행된다

🔹Scenario: PG 환불 실패 시 재처리
  Given 환불 요청이 실패한 상태이다
  And PaymentCancelFailedEvent가 발행되어 EVENT_PUBLICATION 테이블에 기록되었다
  When Spring Modulith의 이벤트 재처리 로직이 실행되면
  Then 1. 실패한 이벤트가 자동으로 재처리된다
  And 2. 재처리 성공 시 EVENT_PUBLICATION 테이블에서 해당 이벤트가 완료 처리된다
  And 3. 재처리 실패 시 이벤트는 계속 재처리 대상으로 남는다

🔹Scenario: 환불 상태 검증
  Given 환불이 성공한 Payment가 존재한다
  When Payment의 상태를 확인하면
  Then 1. status는 CANCELED이다
  And 2. cancelType은 REFUND이다 (CancelType enum)
  And 3. canceledAt은 환불 처리 시각이다
  And 4. Cancel 엔티티가 존재하며 취소 금액과 사유가 기록되어 있다
```

## 관련 클래스

| 클래스 | 역할 |
|--------|------|
| FundingScheduler | 주기적으로 만료된 펀딩 조회 및 처리 |
| FundingExpireUseCase | 펀딩 만료 로직 수행 |
| FundingCloseUseCase | 펀딩 거절(refuse) 로직 수행 |
| Funding | 펀딩 도메인 모델 (상태: IN_PROGRESS → EXPIRED 또는 ACHIEVED → REFUSED) |
| FundingExpiredEvent | 펀딩 만료 이벤트 |
| FundingCanceledEvent | 펀딩 거절 이벤트 |
| OrderEventListener | 펀딩 이벤트 수신 및 환불 처리 시작 |
| FundingOrderService | 펀딩 관련 주문 취소 로직 |
| CancelPaymentService | 결제 취소 및 환불 처리 |
| Payment | 결제 도메인 모델 (상태: PAID → CANCELED) |
| TossPaymentsGatewayAdapter | Toss Payments PG 연동 어댑터 |
| Cancel | 취소 내역 엔티티 |

## 상태값 정의

### FundingStatus
- **IN_PROGRESS**: 펀딩 진행 중
- **ACHIEVED**: 목표액 달성 및 수령자 확정 대기 중
- **EXPIRED**: 기한 만료
- **REFUSED**: 수령자 거절
- **CLOSED**: 시스템에 의한 펀딩 종료

### PaymentStatus
- **PENDING**: 결제 대기
- **PAID**: 결제 완료
- **PARTIALLY_CANCELED**: 부분 취소
- **CANCELED**: 취소 완료
- **FAILED**: 결제 실패

### CancelType
- **REFUND**: PG 환불 처리 (결제 후 취소)
- **CANCEL**: PG 환불 없이 취소 (결제 전 취소)

## 이벤트 재처리 메커니즘

환불 실패 시 별도의 재시도 큐가 아닌 Spring Modulith의 EVENT_PUBLICATION 테이블을 활용합니다.

| 구성 요소 | 설명 |
|-----------|------|
| @ApplicationModuleListener | 이벤트 리스너 어노테이션, 트랜잭션 커밋 후 비동기 처리 |
| EVENT_PUBLICATION | Spring Modulith가 관리하는 이벤트 저장 테이블 |
| 자동 재처리 | 실패한 이벤트는 자동으로 재처리 대상이 됨 |
| @Retryable | OrderEventListener의 on(FundingExpiredEvent) 메서드에 적용 |
