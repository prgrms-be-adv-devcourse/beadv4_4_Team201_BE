# 4.4 펀딩 종료일 초과 처리 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    participant Scheduler as 스케줄러
    participant Funding as 펀딩 서비스
    participant FundingDB as 펀딩 DB
    participant Payment as 결제 서비스
    participant EventBus as 이벤트 버스
    participant Wishlist as 위시리스트 서비스
    participant WishlistDB as 위시리스트 DB
    participant User as 참여자

    Note over Scheduler: 종료일 도래 (end_at < now)

    Scheduler ->> Funding: 종료된 펀딩 처리 요청
    Funding ->> FundingDB: 종료일 초과 & 상태 IN_PREOGRESS펀딩 조회
    FundingDB -->> Funding: 펀딩 목록 반환

    Funding ->> FundingDB: 목표 금액 달성 여부 확인
    FundingDB -->> Funding: 목표 금액 미달

    Funding ->> FundingDB: 펀딩 상태 EXPIRED로 변경
    FundingDB -->> Funding: 상태 변경 완료

    Funding ->> Payment: 참여자 결제 취소/환불 요청
    Payment -->> Funding: 환불 처리 완료

    Funding ->> EventBus: FundingFailedEvent 발행
    EventBus -->> Wishlist: FundingFailedEvent 전달

    Wishlist ->> WishlistDB: 위시리스트 상품 상태 변경 (FUNDING → PENDING)
    WishlistDB -->> Wishlist: 상태 변경 완료

    Funding -->> User: 펀딩 실패 알림 발송
```

## 주요 흐름

1. 스케줄러가 종료일 도래한 펀딩 탐지
2. 종료일 초과 & IN_PROGRESS 상태 펀딩 조회
3. 목표 금액 달성 여부 확인 (미달)
4. 펀딩 상태를 EXPIRED로 변경
5. 참여자 결제 취소/환불 처리
6. FundingFailedEvent 이벤트 발행
7. 위시리스트 상품 상태를 PENDING으로 복원
8. 참여자에게 펀딩 실패 알림 발송

## 핵심 포인트
- **배치 처리**: 스케줄러 기반 자동 만료 처리
- **자동 환불**: 실패 시 참여자 결제 자동 환불
- **상태 복원**: 위시리스트 상품을 PENDING 상태로 되돌림
- **알림 전송**: 모든 참여자에게 실패 알림
