# 4.16 판매자의 상품 재고 관리 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    actor Seller as 판매자
    participant ProductService as 상품 서비스
    participant ProductDB as products 테이블 (stock 컬럼)
    participant StockHistory as product_stock_histories 테이블

    Note over Seller,StockHistory: 시나리오 1: 재고 수량 조회

    Seller->>+ProductService: 상품 관리 페이지 진입
    ProductService->>+ProductDB: 판매자의 상품 목록 조회<br/>(sellerId로 필터링)
    ProductDB-->>-ProductService: Product 목록 반환 (stock 포함)

    ProductService-->>-Seller: 상품 목록 및 재고 수량 표시

    Note over Seller,StockHistory: 시나리오 2: 재고 수정 시 비관적 락 사용 (10개 → 15개)

    Seller->>+ProductService: 상품A 재고 수정 요청<br/>(newStock: 15개)
    ProductService->>+ProductDB: findByIdForUpdate()<br/>(비관적 락)
    ProductDB-->>-ProductService: Product 반환 (현재 stock: 10개)

    ProductService->>ProductService: Product.updateStock(15)<br/>- beforeStock: 10개<br/>- afterStock: 15개<br/>- delta: +5개<br/>- changeType: MANUAL_SELLER

    ProductService->>ProductService: ProductSaleEnabledEvent 발행<br/>(재고 0→15)

    ProductService->>+ProductDB: Product 저장<br/>(stock: 15개)
    ProductDB-->>-ProductService: 저장 완료

    ProductService->>ProductService: ProductStockUpdatedEvent 발행

    Note over StockHistory: 이벤트 리스너가<br/>ProductStockHistory 생성

    ProductService-->>-Seller: 재고 수정 성공

    Note over Seller,StockHistory: 시나리오 3: 재고 0으로 설정 시 이벤트 발행

    Seller->>+ProductService: 상품A 재고 0으로 변경 요청
    ProductService->>+ProductDB: findByIdForUpdate()
    ProductDB-->>-ProductService: Product (stock: 10)

    ProductService->>ProductService: Product.updateStock(0)<br/>- beforeStock: 10<br/>- afterStock: 0<br/>- status는 ACTIVE 유지

    ProductService->>ProductService: ProductSaleDisabledEvent 발행<br/>(재고 > 0 → 0)

    ProductService->>+ProductDB: Product 저장<br/>(stock: 0, status: ACTIVE)
    ProductDB-->>-ProductService: 저장 완료

    ProductService-->>-Seller: 재고 0으로 설정 완료

    Note over ProductDB: ProductStatus는 ACTIVE 유지<br/>재고 0일 때 판매 중지 이벤트 발행

    Note over Seller,StockHistory: 시나리오 4: 유효하지 않은 재고 입력

    Seller->>+ProductService: 상품A 재고 수정 요청<br/>(음수)
    ProductService->>+ProductDB: findById() (일반 조회)
    ProductDB-->>-ProductService: Product 반환

    ProductService->>ProductService: 유효성 검증 실패<br/>(stock < 0)

    ProductService-->>-Seller: 에러: INVALID_PRODUCT_STOCK<br/>"유효하지 않은 재고 수량입니다"

    Note over Seller,StockHistory: 시나리오 5: 주문 완료 시 재고 자동 차감

    participant OrderService as 주문 서비스

    Note over ProductDB: 상품A 재고: 5개

    OrderService->>OrderService: 주문 결제 완료
    OrderService->>+ProductService: 재고 차감 요청<br/>(productId, quantity: 1)

    ProductService->>+ProductDB: findById() (주문 시점)
    ProductDB-->>-ProductService: Product (stock: 5)

    ProductService->>ProductService: Product.decreaseStock(1)<br/>- 재고 검증: 5 >= 1<br/>- beforeStock: 5<br/>- afterStock: 4<br/>- delta: -1<br/>- changeType: ORDER_COMPLETED

    ProductService->>+ProductDB: Product 저장<br/>(stock: 4)
    ProductDB-->>-ProductService: 저장 완료

    ProductService->>ProductService: ProductStockUpdatedEvent 발행

    Note over StockHistory: 이벤트 리스너가<br/>ProductStockHistory 생성

    ProductService-->>-OrderService: 재고 차감 완료

    Note over ProductDB: 재고가 0이 되면<br/>ProductSaleDisabledEvent 발행
```

## 주요 흐름

### 1. 재고 수량 조회
1. 판매자가 상품 관리 페이지 진입
2. ProductService가 sellerId로 상품 목록 조회
3. Product 엔티티에 stock 컬럼이 포함되어 있음 (별도 재고 테이블 없음)
4. 상품 목록 및 재고 수량 표시

### 2. 재고 수정 시 비관적 락 사용 (10개 → 15개)
1. 판매자가 상품A 재고 수정 요청 (newStock: 15개)
2. ProductService가 findByIdForUpdate()로 비관적 락 획득 (ProductService.java:169-189)
3. Product.updateStock(15) 호출
4. beforeStock: 10, afterStock: 15, delta: +5, changeType: MANUAL_SELLER
5. 재고 0→15 전환 시 ProductSaleEnabledEvent 발행 (Product.java:144-146)
6. ProductStockUpdatedEvent 발행 (Product.java:148)
7. 이벤트 리스너가 ProductStockHistory 생성
8. 재고 수정 성공 응답

### 3. 재고 0으로 설정 시 이벤트 발행
1. 판매자가 상품A 재고 0으로 변경 요청
2. Product.updateStock(0) 호출
3. beforeStock: 10, afterStock: 0
4. ProductSaleDisabledEvent 발행 (Product.java:141-143)
5. ProductStatus는 ACTIVE 유지 (SOLDOUT 상태 없음)
6. 재고 0 설정 완료
7. 프론트엔드에서 품절 표시 처리

### 4. 유효하지 않은 재고 입력
1. 판매자가 음수 재고 입력
2. Product 생성/수정 시 validateCreation() 호출 (Product.java:58-59)
3. stock < 0 검증 실패
4. 에러 코드 INVALID_PRODUCT_STOCK 반환

### 5. 주문 완료 시 재고 자동 차감
1. 주문 결제 완료
2. ProductService가 재고 차감 요청 받음
3. Product.decreaseStock(quantity) 호출 (Product.java:152-162)
4. validateStockForOrder()로 재고 충분 여부 확인 (Product.java:176-180)
5. stock 감소 (5개 → 4개)
6. delta: -1, changeType: ORDER_COMPLETED
7. ProductStockUpdatedEvent 발행
8. 재고가 0이 되면 ProductSaleDisabledEvent 발행 (Product.java:158-159)

## 핵심 포인트
- **서비스명**: InventoryService 없음, ProductService가 재고 관리 담당
- **재고 저장**: 별도 재고 테이블 없음, products 테이블의 stock 컬럼 사용
- **이력 테이블**: ProductStockHistory (product_stock_histories)
- **상태**: ProductStatus에 SOLDOUT 없음 (DRAFT, REJECTED, ACTIVE, INACTIVE만 존재)
- **재고 0 처리**: ProductSaleDisabledEvent 발행, 상태는 ACTIVE 유지
- **비관적 락**: 재고 수정 시 findByIdForUpdate() 사용 (다른 필드 수정 시에는 일반 조회)
- **재고 변경 메서드**: Product.updateStock() (수동), decreaseStock() (주문), increaseStock() (반품)
- **이벤트**: ProductStockUpdatedEvent, ProductSaleDisabledEvent, ProductSaleEnabledEvent
- **검증**: stock < 0 입력 시 INVALID_PRODUCT_STOCK 에러
