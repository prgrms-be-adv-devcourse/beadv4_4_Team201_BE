# 4.8 예치금 충전 완료 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    actor User as 사용자
    participant Payment as 결제 모듈
    participant PaymentSucceededEventHandler as PaymentSucceededEventHandler
    participant WalletService as WalletService
    participant WalletDB as Wallet DB
    participant WalletHistoryDB as WalletHistory DB
    participant EventPublisher as EventPublisher

    Note over WalletDB: 초기 잔액: 20,000원

    User->>+Payment: DEPOSIT_CHARGE 결제 요청<br/>(10,000원)
    Payment->>Payment: 토스페이먼츠 결제 처리

    alt 결제 성공
        Payment->>EventPublisher: PaymentSucceededEvent 발행<br/>(paymentType: DEPOSIT_CHARGE)
        Payment-->>-User: 결제 성공 응답

        EventPublisher->>+PaymentSucceededEventHandler: @ApplicationModuleListener<br/>handle(PaymentSucceededEvent)

        Note over PaymentSucceededEventHandler: paymentType이<br/>DEPOSIT_CHARGE인지 확인

        PaymentSucceededEventHandler->>+WalletService: charge(ChargeWalletCommand)<br/>(memberId, amount, orderNumber)

        WalletService->>WalletHistoryDB: 중복 거래 확인<br/>(referenceId + CHARGE)
        WalletHistoryDB-->>WalletService: 중복 없음

        WalletService->>WalletDB: 지갑 조회 (memberId)
        WalletDB-->>WalletService: Wallet 반환

        WalletService->>WalletService: wallet.charge(amount)<br/>(최소 1,000원 검증)
        Note over WalletService: 잔액: 20,000 + 10,000<br/>= 30,000원

        WalletService->>WalletDB: 지갑 저장
        WalletDB-->>WalletService: 저장 완료

        WalletService->>WalletHistoryDB: 거래 내역 기록<br/>(CHARGE, +10,000원)
        WalletHistoryDB-->>WalletService: 내역 저장 완료

        WalletService->>EventPublisher: WalletChargedEvent 발행

        WalletService-->>-PaymentSucceededEventHandler: ChargeWalletResult 반환
        PaymentSucceededEventHandler-->>-EventPublisher: 이벤트 처리 완료

    else 결제 실패
        Payment-->>-User: 결제 실패 응답<br/>("결제에 실패했습니다")
        Note over WalletDB: 이벤트 미발행<br/>지갑 잔액 변경 없음
    end

    Note over WalletDB: 성공 시 잔액: 30,000원<br/>실패 시 잔액: 20,000원 (변경 없음)
```

## 주요 흐름

### 성공 시나리오
1. 사용자가 PaymentType.DEPOSIT_CHARGE로 결제 요청 (10,000원)
2. Payment 모듈이 토스페이먼츠 결제 처리
3. 결제 성공 시 `PaymentSucceededEvent` 발행
4. `PaymentSucceededEventHandler`가 이벤트 수신
5. paymentType이 DEPOSIT_CHARGE인지 확인
6. `WalletService.charge()` 호출
7. 중복 거래 검증 (referenceId + ReferenceType.CHARGE)
8. 지갑 조회 또는 생성
9. `Wallet.charge()` - 최소 충전금액(1,000원) 검증 후 잔액 증가
10. 지갑 저장 (20,000 + 10,000 = 30,000원)
11. WalletHistory 기록 (TransactionType.CHARGE, ReferenceType.CHARGE)
12. `WalletChargedEvent` 발행
13. 충전 완료

### 실패 시나리오
1. 사용자가 DEPOSIT_CHARGE 결제 요청
2. 토스페이먼츠 결제 실패
3. 결제 실패 응답 반환
4. **이벤트 미발행** - WalletService 호출 없음
5. 지갑 잔액 변경 없음
6. WalletHistory 기록 없음

## 핵심 포인트
- **이벤트 기반 충전**: 결제 완료 후 `PaymentSucceededEvent`로 트리거
- **공개 API 없음**: 사용자가 직접 충전 API를 호출하지 않음
- **중복 방지**: referenceId(orderNumber) + ReferenceType.CHARGE로 멱등성 보장
- **트랜잭션**: 결제 성공 시에만 지갑 잔액 업데이트
- **실패 처리**: 결제 실패 시 이벤트 자체가 발행되지 않아 WalletHistory에 실패 내역 기록 안 됨
- **자동 지갑 생성**: 지갑이 없으면 잔액 0원으로 생성 후 충전
- **최소 충전금액**: 1,000원 미만 충전 불가 (WalletErrorCode.CHARGE_AMOUNT_BELOW_MINIMUM)
