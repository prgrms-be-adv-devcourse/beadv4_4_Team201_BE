# 4.9 예치금 출금 완료 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    actor User as 사용자
    participant WalletService as 지갑 서비스
    participant WithdrawalDB as 출금 요청 DB
    participant WalletDB as 지갑 DB
    participant BankAPI as 외부 이체 API
    participant WalletHistory as 지갑 내역

    Note over WalletDB: 초기 잔액: 50,000원

    %% 출금 요청 생성
    User->>+WalletService: 30,000원 출금 요청
    WalletService->>+WithdrawalDB: 출금 요청 생성 (REQUESTED)
    WithdrawalDB-->>-WalletService: 출금 요청 ID 반환

    %% 출금 가능 여부 검증 및 처리 시작
    WalletService->>+WalletDB: 잔액 확인 (50,000원)
    WalletDB-->>-WalletService: 잔액 충분

    WalletService->>+WithdrawalDB: 출금 요청 상태 변경 (REQUESTED → PROCESSING)
    WithdrawalDB-->>-WalletService: 상태 변경 완료

    WalletService-->>-User: 출금 처리 시작 응답

    %% 외부 이체 처리
    WalletService->>+BankAPI: 외부 이체 요청 (30,000원)

    alt 이체 성공
        BankAPI-->>WalletService: 이체 성공
        deactivate BankAPI

        WalletService->>+WalletDB: 잔액 차감<br/>(50,000 - 30,000 = 20,000원)
        WalletDB-->>-WalletService: 잔액 업데이트 완료

        WalletService->>+WithdrawalDB: 출금 요청 상태 변경<br/>(PROCESSING → COMPLETED)
        WithdrawalDB-->>-WalletService: 상태 변경 완료

        WalletService->>+WalletHistory: 출금 내역 기록<br/>(-30,000원)
        WalletHistory-->>-WalletService: 내역 저장 완료

        WalletService->>User: 출금 완료 알림<br/>(잔액: 20,000원)

    else 이체 실패
        BankAPI-->>WalletService: 이체 실패

        WalletService->>+WithdrawalDB: 출금 요청 상태 변경<br/>(PROCESSING → FAILED)
        WithdrawalDB-->>-WalletService: 상태 변경 완료

        WalletService->>+WalletHistory: 출금 실패 내역 기록
        WalletHistory-->>-WalletService: 내역 저장 완료

        WalletService->>User: 출금 실패 알림
    end

    Note over WalletDB: 성공 시 잔액: 20,000원<br/>실패 시 잔액: 50,000원 (변경 없음)

    %% 잔액 부족 시나리오
    Note over User,WalletHistory: --- 잔액 부족 시나리오 ---

    User->>+WalletService: 30,000원 출금 요청<br/>(현재 잔액: 10,000원)
    WalletService->>+WithdrawalDB: 출금 요청 생성 (REQUESTED)
    WithdrawalDB-->>-WalletService: 출금 요청 ID 반환

    WalletService->>+WalletDB: 잔액 확인 (10,000원)
    WalletDB-->>-WalletService: 잔액 부족

    WalletService->>+WithdrawalDB: 출금 요청 상태 변경<br/>(REQUESTED → FAILED)
    WithdrawalDB-->>-WalletService: 상태 변경 완료

    WalletService->>+WalletHistory: 출금 실패 내역 기록
    WalletHistory-->>-WalletService: 내역 저장 완료

    WalletService-->>-User: "잔액이 부족합니다" 오류 반환
```

## 주요 흐름

### 성공 시나리오
1. 사용자가 30,000원 출금 요청
2. 출금 요청 생성 (REQUESTED)
3. 잔액 확인 (50,000원 - 충분함)
4. 출금 요청 상태를 PROCESSING으로 변경
5. 외부 이체 API 호출
6. 이체 성공
7. 지갑 잔액 차감 (50,000 - 30,000 = 20,000원)
8. 출금 요청 상태를 COMPLETED로 변경
9. 출금 내역 기록
10. 출금 완료 알림

### 이체 실패 시나리오
1. 외부 이체 실패
2. 출금 요청 상태를 FAILED로 변경
3. 출금 실패 내역 기록
4. 잔액은 변경되지 않음
5. 출금 실패 알림

### 잔액 부족 시나리오
1. 사용자가 30,000원 출금 요청 (현재 잔액: 10,000원)
2. 출금 요청 생성 (REQUESTED)
3. 잔액 확인 (10,000원 - 부족함)
4. 출금 요청 상태를 FAILED로 변경
5. 출금 실패 내역 기록
6. "잔액이 부족합니다" 오류 반환

## 핵심 포인트
- **상태 관리**: REQUESTED → PROCESSING → COMPLETED/FAILED 상태 전이
- **비동기 처리**: 외부 이체는 비동기로 처리
- **트랜잭션**: 이체 성공 시에만 잔액 차감
- **검증**: 출금 전 잔액 충분 여부 검증
- **이력 관리**: 모든 출금 시도 내역 기록
