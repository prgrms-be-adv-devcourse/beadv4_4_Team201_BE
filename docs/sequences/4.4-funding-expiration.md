# 4.4 펀딩 종료일 초과 처리 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    participant Scheduler as FundingScheduler
    participant Funding as FundingExpireUseCase
    participant FundingDB as 펀딩 DB
    participant EventBus as 이벤트 버스
    participant Order as OrderEventListener
    participant Payment as CancelPaymentService
    participant Wishlist as WishlistEventListener
    participant WishlistDB as 위시리스트 DB
    participant User as 참여자

    Note over Scheduler: 매일 00:00 실행<br/>@Scheduled(cron = "0 0 0 * * *")

    Scheduler ->> Funding: 종료된 펀딩 처리 요청
    Funding ->> FundingDB: 종료일 초과 & 상태 IN_PROGRESS 펀딩 조회
    FundingDB -->> Funding: 펀딩 목록 반환

    Funding ->> FundingDB: 목표 금액 달성 여부 확인
    FundingDB -->> Funding: 목표 금액 미달

    Funding ->> FundingDB: 펀딩 상태 EXPIRED로 변경<br/>closedAt 기록
    FundingDB -->> Funding: 상태 변경 완료

    Funding ->> EventBus: FundingExpiredEvent 발행

    EventBus ->> Order: FundingExpiredEvent 전달
    Order ->> Payment: 참여자 결제 취소/환불 요청
    Payment -->> Order: 환불 처리 완료

    EventBus ->> Wishlist: FundingExpiredEvent 전달
    Wishlist ->> WishlistDB: 위시리스트 상품 상태 변경 (IN_PROGRESS → PENDING)
    WishlistDB -->> Wishlist: 상태 변경 완료

    Funding -->> User: 펀딩 실패 알림 발송
```

## 주요 흐름

1. FundingScheduler가 매일 00:00에 자동 실행 (@Scheduled)
2. 종료일 초과 & IN_PROGRESS 상태 펀딩 조회
3. 목표 금액 달성 여부 확인 (미달)
4. 펀딩 상태를 EXPIRED로 변경, closedAt 기록
5. FundingExpiredEvent 이벤트 발행
6. OrderEventListener가 환불 처리 (CancelPaymentService)
7. WishlistEventListener가 위시리스트 상품 상태를 PENDING으로 복원
8. 참여자에게 펀딩 실패 알림 발송

## 핵심 포인트
- **배치 처리**: 매일 00:00 스케줄러 기반 자동 만료 처리
- **이벤트 기반 환불**: FundingExpiredEvent → OrderEventListener → CancelPaymentService
- **상태 복원**: 위시리스트 상품을 PENDING 상태로 되돌림 (IN_PROGRESS → PENDING)
- **알림 전송**: 모든 참여자에게 실패 알림
