# 4.14 판매자의 판매 상품 수정/삭제 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    actor Seller as 판매자
    participant Controller as ProductController
    participant ProductService as ProductService
    participant FundingClientPort as FundingClientPort
    participant ProductDB as Product DB
    participant EventPublisher as EventPublisher

    Note over Seller,EventPublisher: 시나리오 1: 상품 정보 수정

    Seller->>+Controller: PATCH /api/v2/products/my/{id}<br/>(name, description, price 등)
    Controller->>+ProductService: updateProduct(productId, sellerId, dto)

    ProductService->>ProductDB: 상품 조회 (findById)
    ProductDB-->>ProductService: Product 반환

    ProductService->>ProductService: 소유자 검증<br/>(sellerId 일치 확인)
    ProductService->>ProductService: 삭제 여부 검증<br/>(deletedAt == null)

    ProductService->>ProductService: product.updateName(newName)<br/>product.updatePrice(newPrice)<br/>등 setter 호출

    ProductService->>ProductDB: 상품 저장
    ProductDB-->>ProductService: 저장 완료

    ProductService->>EventPublisher: ProductUpdatedEvent 발행
    ProductService-->>-Controller: ProductUpdateResult 반환
    Controller-->>-Seller: 상품 수정 성공 (200 OK)

    Note over Seller,EventPublisher: 시나리오 2: 판매 중지 (INACTIVE 전환)

    Seller->>+Controller: PATCH /api/v2/products/my/{id}<br/>(status: INACTIVE)
    Controller->>+ProductService: updateProduct(productId, sellerId, dto)

    ProductService->>ProductDB: 상품 조회
    ProductDB-->>ProductService: Product (ACTIVE)

    ProductService->>ProductService: 소유자/삭제 검증

    ProductService->>+FundingClientPort: checkFundingExistsByProductId(productId)
    Note over FundingClientPort: Internal API 호출<br/>진행 중인 펀딩 확인
    FundingClientPort-->>-ProductService: false (펀딩 없음)

    ProductService->>ProductService: product.inActive()
    Note over ProductService: ACTIVE → INACTIVE<br/>ProductSaleDisabledEvent 등록

    ProductService->>ProductDB: 상품 저장
    ProductService->>EventPublisher: ProductSaleDisabledEvent 발행
    ProductService->>EventPublisher: ProductUpdatedEvent 발행

    ProductService-->>-Controller: ProductUpdateResult 반환
    Controller-->>-Seller: 상태 변경 성공 (200 OK)

    Note over Seller,EventPublisher: 시나리오 3: 진행 중인 펀딩이 있어 판매 중지 실패

    Seller->>+Controller: PATCH /api/v2/products/my/{id}<br/>(status: INACTIVE)
    Controller->>+ProductService: updateProduct(...)

    ProductService->>ProductDB: 상품 조회
    ProductDB-->>ProductService: Product (ACTIVE)

    ProductService->>+FundingClientPort: checkFundingExistsByProductId(productId)
    FundingClientPort-->>-ProductService: true (진행 중 펀딩 존재)

    ProductService->>ProductService: ProductException<br/>(CANNOT_STOP_SALE_DUE_TO_ACTIVE_FUNDING)

    ProductService-->>-Controller: 예외 발생
    Controller-->>-Seller: 400 Bad Request<br/>"진행 중인 펀딩이 있습니다"

    Note over Seller,EventPublisher: 시나리오 4: 상품 삭제 (Soft Delete)

    Seller->>+Controller: DELETE /api/v2/products/my/{id}
    Controller->>+ProductService: deleteProduct(productId, sellerId)

    ProductService->>ProductDB: findByIdAndSellerId(productId, sellerId)
    ProductDB-->>ProductService: Product (INACTIVE)

    ProductService->>ProductService: product.delete()
    Note over ProductService: 상태 검증: INACTIVE만 삭제 가능<br/>deletedAt = now()

    ProductService->>ProductDB: 상품 저장
    ProductDB-->>ProductService: 저장 완료

    ProductService->>EventPublisher: ProductDeletedEvent 발행

    ProductService-->>-Controller: void 반환
    Controller-->>-Seller: 삭제 성공 (204 No Content)

    Note over Seller,EventPublisher: 시나리오 5: ACTIVE 상품 삭제 시도 실패

    Seller->>+Controller: DELETE /api/v2/products/my/{id}
    Controller->>+ProductService: deleteProduct(productId, sellerId)

    ProductService->>ProductDB: 상품 조회
    ProductDB-->>ProductService: Product (ACTIVE)

    ProductService->>ProductService: product.delete()
    Note over ProductService: ProductException<br/>(PRODUCT_NOT_IN_INACTIVE_STATUS)

    ProductService-->>-Controller: 예외 발생
    Controller-->>-Seller: 400 Bad Request<br/>"INACTIVE 상품만 삭제 가능"
```

## 주요 흐름

### 1. 상품 정보 수정
1. 판매자가 `PATCH /api/v2/products/my/{id}` 요청
2. 상품 조회 후 소유자 검증
3. 삭제되지 않은 상품인지 확인
4. `product.updateName()`, `product.updatePrice()` 등 호출
5. 상품 저장 후 `ProductUpdatedEvent` 발행
6. 수정 성공 응답

### 2. 판매 중지 (ACTIVE → INACTIVE)
1. 판매자가 `status: INACTIVE`로 수정 요청
2. `FundingClientPort.checkFundingExistsByProductId()` 호출
3. 진행 중인 펀딩이 없으면 `product.inActive()` 호출
4. ACTIVE → INACTIVE 전환 (`ProductSaleDisabledEvent` 등록)
5. 상품 저장 후 이벤트 발행
6. 상태 변경 성공

### 3. 진행 중인 펀딩으로 판매 중지 실패
1. 판매자가 `status: INACTIVE`로 수정 요청
2. `FundingClientPort.checkFundingExistsByProductId()` → true
3. `ProductException(CANNOT_STOP_SALE_DUE_TO_ACTIVE_FUNDING)` 발생
4. 400 Bad Request 응답

### 4. 상품 삭제 (Soft Delete)
1. 판매자가 `DELETE /api/v2/products/my/{id}` 요청
2. 상품 조회 및 소유자 확인
3. `product.delete()` 호출
4. 상태 검증: INACTIVE 상품만 삭제 가능
5. `deletedAt = now()` 설정
6. `ProductDeletedEvent` 발행
7. 삭제 성공 (204 No Content)

### 5. ACTIVE 상품 삭제 시도 실패
1. 판매자가 ACTIVE 상품 삭제 시도
2. `product.delete()` 내부에서 상태 검증
3. `ProductException(PRODUCT_NOT_IN_INACTIVE_STATUS)` 발생
4. 400 Bad Request 응답

## 핵심 포인트
- **결제 내역 검증 없음**: 현재 구현에는 Payment 확인 로직이 없음 (펀딩만 확인)
- **펀딩 진행 여부 확인**: INACTIVE 전환 시 `FundingClientPort`로 펀딩 존재 여부 확인
- **BC 경계 준수**: Port 인터페이스를 통한 모듈 간 통신
- **철회 개념 없음**: "철회"는 없고 "판매 중지(INACTIVE)"와 "삭제(Soft Delete)"만 존재
- **삭제 조건**: INACTIVE 상태에서만 삭제 가능
- **Soft Delete**: `deletedAt` 타임스탬프로 관리, Hard Delete는 배치로 처리
