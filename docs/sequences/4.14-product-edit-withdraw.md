# 4.14 판매자의 판매 상품 수정/철회 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    actor Seller as 판매자
    participant ProductService as 상품 서비스
    participant PaymentService as 결제 서비스
    participant ProductDB as 상품 DB
    participant PaymentDB as 결제 DB

    Note over Seller,PaymentDB: 시나리오 1: 상품 정보 수정 (결제 발생 전)

    Seller->>+ProductService: 상품 정보 수정 요청<br/>(상품 ID, 수정 데이터)
    ProductService->>+ProductDB: 상품 조회<br/>(Status: ACTIVE)
    ProductDB-->>-ProductService: 상품 정보 반환

    ProductService->>+PaymentService: 결제 내역 확인
    PaymentService->>+PaymentDB: 상품에 대한 결제 조회
    PaymentDB-->>-PaymentService: 결제 내역 없음
    PaymentService-->>-ProductService: 결제 발생 없음

    ProductService->>+ProductDB: 상품 정보 업데이트
    ProductDB-->>-ProductService: 업데이트 완료

    ProductService-->>-Seller: 상품 수정 성공

    Note over Seller,PaymentDB: 시나리오 2: 핵심 정보 수정 제한 (결제 발생 후)

    Seller->>+ProductService: 상품 가격 수정 요청<br/>(상품 ID, 새 가격)
    ProductService->>+ProductDB: 상품 조회<br/>(Status: ACTIVE)
    ProductDB-->>-ProductService: 상품 정보 반환

    ProductService->>+PaymentService: 결제 내역 확인
    PaymentService->>+PaymentDB: 상품에 대한 결제 조회
    PaymentDB-->>-PaymentService: 결제 내역 존재
    PaymentService-->>-ProductService: 결제 발생 확인

    ProductService->>ProductService: 핵심 정보 수정 검증 실패<br/>(가격 변경 불가)

    ProductService-->>-Seller: "이미 결제가 발생한 상품은<br/>주요 정보를 수정할 수 없습니다" 오류

    Note over Seller,PaymentDB: 시나리오 3: 상품 철회 (결제 발생 전)

    Seller->>+ProductService: 상품 철회 요청<br/>(상품 ID)
    ProductService->>+ProductDB: 상품 조회<br/>(Status: ACTIVE)
    ProductDB-->>-ProductService: 상품 정보 반환

    ProductService->>+PaymentService: 결제 내역 확인
    PaymentService->>+PaymentDB: 상품에 대한 결제 조회
    PaymentDB-->>-PaymentService: 결제 내역 없음
    PaymentService-->>-ProductService: 결제 발생 없음

    ProductService->>+ProductDB: 상품 상태 변경<br/>(ACTIVE → INACTIVE)
    ProductDB-->>-ProductService: 상태 변경 완료

    ProductService-->>-Seller: 상품 철회 성공

    Note over ProductDB: 상품 상태: INACTIVE<br/>(사용자에게 미노출)

    Note over Seller,PaymentDB: 시나리오 4: 상품 철회 제한 (결제 발생 후)

    Seller->>+ProductService: 상품 철회 요청<br/>(상품 ID)
    ProductService->>+ProductDB: 상품 조회<br/>(Status: ACTIVE)
    ProductDB-->>-ProductService: 상품 정보 반환

    ProductService->>+PaymentService: 결제 내역 확인
    PaymentService->>+PaymentDB: 상품에 대한 결제 조회
    PaymentDB-->>-PaymentService: 결제 내역 존재
    PaymentService-->>-ProductService: 결제 발생 확인

    ProductService->>ProductService: 철회 검증 실패<br/>(결제 발생)

    ProductService-->>-Seller: "이미 판매된 상품은<br/>철회할 수 없습니다" 오류
```

## 주요 흐름

### 1. 상품 정보 수정 (결제 발생 전)
1. 판매자가 상품 정보 수정 요청
2. 상품 조회 (ACTIVE 상태)
3. 결제 내역 확인 (결제 없음)
4. 상품 정보 업데이트
5. 수정 성공 응답
6. 수정된 정보는 즉시 사용자에게 노출

### 2. 핵심 정보 수정 제한 (결제 발생 후)
1. 판매자가 가격 수정 요청
2. 상품 조회 (ACTIVE 상태)
3. 결제 내역 확인 (결제 존재)
4. 핵심 정보 수정 검증 실패
5. "이미 결제가 발생한 상품은 주요 정보를 수정할 수 없습니다" 오류 반환

### 3. 상품 철회 (결제 발생 전)
1. 판매자가 상품 철회 요청
2. 상품 조회 (ACTIVE 상태)
3. 결제 내역 확인 (결제 없음)
4. 상품 상태를 INACTIVE로 변경
5. 철회 성공 응답
6. 사용자에게 더 이상 노출되지 않음

### 4. 상품 철회 제한 (결제 발생 후)
1. 판매자가 상품 철회 요청
2. 상품 조회 (ACTIVE 상태)
3. 결제 내역 확인 (결제 존재)
4. 철회 검증 실패
5. "이미 판매된 상품은 철회할 수 없습니다" 오류 반환

## 핵심 포인트
- **결제 내역 검증**: 수정/철회 전 결제 발생 여부 확인
- **핵심 정보 보호**: 결제 발생 후 가격 등 핵심 정보 수정 불가
- **철회 제한**: 결제 발생 후 상품 철회 불가
- **명확한 오류**: 각 제한 케이스별 명확한 오류 메시지
