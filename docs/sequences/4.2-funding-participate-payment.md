# 4.2 펀딩 참여 및 결제 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    actor UserA as 사용자 A
    actor UserB as 사용자 B
    participant UI as 펀딩 참여 화면
    participant Funding as FundingContributeUseCase
    participant DB as 펀딩 DB
    participant Payment as Payment 모듈
    participant PG as 결제(PG)

    Note over Funding,DB: 현재 남은 금액 = 1,000원<br/>@Version 기반 낙관적 락

    UserA ->> UI: 1,000원 결제 요청
    UserB ->> UI: 1,000원 결제 요청

    UI ->> Funding: 결제 요청 전달 (User A)
    Funding ->> DB: 펀딩 상태 조회 + 금액 확인
    DB -->> Funding: 남은 금액 1,000원, Version=1
    Funding ->> DB: 펀딩 금액 업데이트 (1,000원 차감, Version=2)
    DB -->> Funding: 업데이트 성공
    Funding ->> Payment: 결제 승인 요청 (User A)
    Payment ->> PG: PG 결제 승인 요청
    PG -->> Payment: 결제 성공
    Payment -->> Funding: 결제 성공
    Funding -->> UI: 결제 성공 응답 (User A)

    UI ->> Funding: 결제 요청 전달 (User B)
    Funding ->> DB: 펀딩 상태 조회
    DB -->> Funding: 펀딩 상태 = ACHIEVED
    Funding -->> UI: 결제 실패 응답
    UI -->> UserB: "진행 중인 펀딩이 아닙니다" 오류 표시
```

## 주요 흐름

1. User A와 User B가 동시에 결제 시도
2. User A의 요청이 먼저 도착하여 처리 시작 (Version=1)
3. 남은 금액 확인 후 펀딩 금액 업데이트 (Version=2)
4. Payment 모듈을 통해 PG 결제 승인 처리
5. User A 결제 승인 및 완료
6. User B의 요청 처리 시 이미 펀딩 달성 상태 (ACHIEVED)
7. User B에게 실패 응답 반환 (NOT_IN_PROGRESS 예외)

## 핵심 포인트
- **동시성 제어**: @Version 기반 낙관적 락을 통한 순차 처리
- **모듈 분리**: Payment 모듈이 PG 연동 담당 (TossPaymentsGatewayAdapter)
- **멱등성**: 동일 결제 요청 중복 방지
- **실패 처리**: 명확한 오류 메시지 제공 (FundingErrorCode.NOT_IN_PROGRESS)
