# 4.3 펀딩 완료 처리 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    actor UserA as 사용자 A
    actor UserB as 사용자 B
    participant PaymentAPI as 결제 API
    participant FundingService as FundingContributeUseCase
    participant FundingDB as 펀딩 DB
    participant EventBus as 이벤트 버스
    participant Wishlist as WishlistEventListener

    Note over FundingDB: 초기 상태<br/>목표: 50,000원<br/>누적: 45,000원<br/>Status: IN_PROGRESS

    %% 사용자 A의 결제 프로세스
    UserA->>+PaymentAPI: 5,000원 결제 요청
    PaymentAPI->>+FundingService: 결제 가능 여부 확인
    FundingService->>+FundingDB: 펀딩 상태 조회
    FundingDB-->>-FundingService: Status: IN_PROGRESS
    FundingService-->>-PaymentAPI: 결제 가능

    PaymentAPI->>PaymentAPI: 결제 처리
    PaymentAPI->>+FundingService: 결제 완료 통지 (5,000원)

    FundingService->>+FundingDB: 누적 금액 업데이트<br/>(45,000 + 5,000 = 50,000원)
    FundingDB-->>-FundingService: 업데이트 완료

    %% 목표 달성 확인 및 자동 완료 처리
    FundingService->>FundingService: 목표 금액 달성 확인<br/>(50,000 >= 50,000)

    activate FundingService
    Note over FundingService: 자동 완료 프로세스 시작

    FundingService->>+FundingDB: 1. 펀딩 상태 변경<br/>(IN_PROGRESS → ACHIEVED)
    FundingDB-->>-FundingService: 상태 변경 완료

    FundingService->>+FundingDB: 2. achievedAt 필드에 달성 시각 기록<br/>(현재 시각)
    FundingDB-->>-FundingService: 달성 시각 기록 완료

    FundingService->>+EventBus: FundingAchievedEvent 발행
    EventBus->>+Wishlist: FundingAchievedEvent 전달
    Wishlist->>Wishlist: 위시리스트 상태 변경<br/>(IN_PROGRESS → REQUESTED_CONFIRM)
    Wishlist-->>-EventBus: 처리 완료
    deactivate FundingService

    FundingService-->>-PaymentAPI: 결제 처리 완료
    PaymentAPI-->>-UserA: 결제 성공 응답

    Note over FundingDB: 최종 상태<br/>목표: 50,000원<br/>누적: 50,000원<br/>Status: ACHIEVED<br/>achievedAt: 달성 시각 기록됨

    %% 후속 결제 시도 차단
    UserB->>+PaymentAPI: 결제 요청 시도
    PaymentAPI->>+FundingService: 결제 가능 여부 확인
    FundingService->>+FundingDB: 펀딩 상태 조회
    FundingDB-->>-FundingService: Status: ACHIEVED
    FundingService-->>-PaymentAPI: 결제 불가 (펀딩 종료)
    PaymentAPI-->>-UserB: 결제 실패<br/>(진행 중인 펀딩이 아닙니다)
```

## 주요 흐름

1. 사용자 A가 5,000원 결제 요청
2. 펀딩 상태 확인 (IN_PROGRESS)
3. 결제 처리 및 완료 통지
4. 누적 금액 업데이트 (45,000 + 5,000 = 50,000원)
5. 목표 금액 달성 확인 (contribute 메서드 내부)
6. 펀딩 상태를 ACHIEVED로 자동 변경
7. achievedAt 필드에 달성 시각 기록
8. FundingAchievedEvent 발행
9. WishlistEventListener가 위시리스트 상태를 REQUESTED_CONFIRM으로 변경
10. 사용자 B의 후속 결제 시도는 차단됨

## 핵심 포인트
- **자동 완료**: 목표 금액 달성 시 별도 액션 없이 자동 완료
- **즉시 차단**: 완료 후 추가 결제 요청 즉시 거부
- **달성 시각 기록**: achievedAt 필드에 정확한 달성 시점 추적 (closedAt은 accept/refuse 시에만)
- **이벤트 기반**: FundingAchievedEvent를 통한 위시리스트 상태 전이
