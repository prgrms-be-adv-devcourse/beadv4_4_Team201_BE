# 4.1 펀딩 라이프사이클 (Funding Lifecycle)

## 설명
누군가의 위시리스트 상품에 대해 누군가 처음으로 결제하면 펀딩 프로젝트가 자동으로 시작된다.

## User Story

> *"친구의 위시리스트 상품을 내가 가장 먼저 결제하면, 별도의 개설 절차 없이 즉시 펀딩이 시작되어 다른 친구들도 참여할 수 있다."*

## Acceptance Criteria

```gherkin
Feature: 첫 결제에 의한 펀딩 시작

🔹Scenario: 위시리스트 상품에 첫 결제가 발생함
  Given Friend B가 위시리스트에 50,000원짜리 상품을 등록한 상태
  And 해당 WishlistItem의 상태는 PENDING이다
  When Friend A가 POST /api/v2/orders로 10,000원 결제를 완료하면
  Then 1. CoreFacade.placeOrder()가 Order와 Payment를 생성한다
  And 2. CoreFacade가 FundingFacade.processFundingActions()를 호출한다
  And 3. FundingCreateUseCase.createFunding()이 호출된다
  And 3. Funding.startFunding()으로 새로운 Funding이 생성된다
  And 4. Funding의 상태는 IN_PROGRESS이다
  And 5. Funding의 deadline은 현재 시간 + 15일이다
  And 6. Funding의 currentAmount는 0이다
  And 7. FundingCreatedEvent가 발행된다
  And 8. WishlistEventListener.handleFundingListCreated()가 이벤트를 수신한다
  And 9. WishlistItem의 상태가 PENDING에서 IN_PROGRESS로 변경된다
  And 10. 생성된 Funding에 대한 초기 기여(10,000원)가 처리된다

🔹Scenario: 펀딩 상태 전이 검증
  Given 새로 생성된 Funding이 존재한다
  When Funding의 상태를 확인하면
  Then 1. status는 IN_PROGRESS이다
  And 2. targetAmount는 위시리스트 상품의 원가와 동일하다
  And 3. currentAmount는 초기 기여 금액과 동일하다
  And 4. deadline은 생성 시점 + 15일이다
  And 5. achievedAt은 null이다 (아직 달성되지 않음)
  And 6. closedAt은 null이다 (아직 종료되지 않음)

🔹Scenario: 이벤트 기반 상태 전이 검증
  Given FundingCreatedEvent가 발행된 상태
  When WishlistEventListener가 이벤트를 수신하면
  Then 1. 이벤트의 fundingDetails에서 wishlistItemId를 추출한다
  And 2. 해당 WishlistItem을 조회한다
  And 3. WishlistItem.changeStatus(IN_PROGRESS)를 호출한다
  And 4. WishlistItem의 상태가 IN_PROGRESS로 변경된다
```

## 관련 클래스

| 클래스 | 역할 |
|--------|------|
| OrderController | 주문 생성 엔드포인트 제공 |
| CoreFacade | 주문, 결제 처리 후 FundingFacade 호출 |
| FundingFacade | 펀딩 생성 및 초기 기여를 조율 |
| FundingCreateUseCase | 펀딩 생성 로직 수행 |
| Funding | 펀딩 도메인 모델 (상태: IN_PROGRESS) |
| FundingCreatedEvent | 펀딩 생성 이벤트 |
| WishlistEventListener | 펀딩 이벤트 수신 및 위시리스트 상태 변경 |
| WishlistItem | 위시리스트 상품 (상태: PENDING → IN_PROGRESS) |
