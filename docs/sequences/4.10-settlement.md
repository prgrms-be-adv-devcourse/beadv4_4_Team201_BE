# 4.10 판매금 정산 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    participant Scheduler as 스케줄러
    participant ExecutionService as 정산 실행 서비스
    participant ItemService as 정산 항목 서비스
    participant SettlementQueue as 정산 큐
    participant SettlementHistory as 정산 이력
    participant EventPublisher as 이벤트 발행
    participant WalletSettlementService as 지갑 정산 서비스
    participant WalletDB as 지갑 DB

    Note over Scheduler: 정산 예정일 도래

    %% SettlementItem 생성
    Scheduler->>+ItemService: 정산 항목 생성 배치 실행
    ItemService->>ItemService: 정산 대상 결제 내역 조회
    ItemService->>+SettlementQueue: 판매자별 SettlementItem 생성<br/>(SettlementQueue 등록, Status: READY)
    SettlementQueue-->>-ItemService: 등록 완료
    deactivate ItemService

    Note over SettlementQueue: Status: READY

    %% 정산 실행 (큐 → 이력 생성)
    Scheduler->>+ExecutionService: 정산 실행 배치 실행
    ExecutionService->>+SettlementQueue: READY 상태 큐 조회
    SettlementQueue-->>-ExecutionService: 큐 목록 반환

    ExecutionService->>ExecutionService: 판매자별 정산 금액 집계<br/>(수수료 차감)

    ExecutionService->>+SettlementQueue: 큐 상태 변경<br/>(READY → IN_PROGRESS)
    SettlementQueue-->>-ExecutionService: 상태 변경 완료

    ExecutionService->>+SettlementHistory: SettlementHistory 생성<br/>(Status: CREATED)
    SettlementHistory-->>-ExecutionService: 이력 ID 반환

    ExecutionService->>+SettlementQueue: 큐 상태 변경<br/>(IN_PROGRESS → DONE)
    SettlementQueue-->>-ExecutionService: 상태 변경 완료

    ExecutionService->>+EventPublisher: SettlementCreatedEvent 발행
    EventPublisher-->>-ExecutionService: 이벤트 발행 완료

    deactivate ExecutionService

    %% 지갑 지급 처리
    EventPublisher->>+WalletSettlementService: SettlementCreatedEvent 수신

    WalletSettlementService->>WalletSettlementService: 중복 지급 검증<br/>(WalletHistory 확인)

    alt 중복 아닌 경우
        WalletSettlementService->>+WalletDB: 판매자 지갑 잔액 증가
        WalletDB-->>-WalletSettlementService: 잔액 업데이트 완료

        WalletSettlementService->>WalletSettlementService: WalletHistory 기록<br/>(SETTLEMENT_PAYOUT)

        WalletSettlementService->>+SettlementHistory: 정산 상태 변경<br/>(CREATED → COMPLETED)
        SettlementHistory-->>-WalletSettlementService: 상태 변경 완료

        Note over SettlementHistory: Status: COMPLETED

    else 중복 지급 감지
        WalletSettlementService->>WalletSettlementService: 중복 지급 무시
        Note over WalletSettlementService: 멱등성 보장
    end

    deactivate WalletSettlementService

    %% 실패 시나리오
    Note over Scheduler,WalletDB: --- 실패 시나리오 ---

    EventPublisher->>+WalletSettlementService: SettlementCreatedEvent 수신
    WalletSettlementService->>WalletDB: 판매자 지갑 조회 실패

    WalletSettlementService->>+SettlementHistory: 정산 상태 변경<br/>(CREATED → FAILED)
    SettlementHistory-->>-WalletSettlementService: 상태 변경 완료

    WalletSettlementService->>+SettlementQueue: 큐 상태 변경<br/>(DONE → FAIL)
    SettlementQueue-->>-WalletSettlementService: 상태 변경 완료

    WalletSettlementService->>SettlementQueue: retryCount 증가

    deactivate WalletSettlementService

    Note over SettlementQueue: Status: FAIL<br/>명시적 재시도 로직 미구현
```

## 주요 흐름

### 1. 정산 항목 생성 (SettlementItem)
1. 정산 예정일에 스케줄러 실행
2. 정산 대상 결제 내역 조회 (결제 완료 & 미정산)
3. 판매자별 SettlementItem 생성
4. SettlementQueue에 등록 (READY 상태)

### 2. 정산 실행 (SettlementQueue → SettlementHistory)
1. READY 상태 큐 조회
2. 판매자별 정산 금액 집계 (수수료 차감)
3. 큐 상태를 IN_PROGRESS로 변경
4. SettlementHistory 생성 (CREATED 상태)
5. 큐 상태를 DONE으로 변경
6. SettlementCreatedEvent 발행

### 3. 지갑 지급 처리 (WalletSettlementService)
1. SettlementCreatedEvent 수신
2. WalletHistory에서 중복 지급 검증 (멱등성)
3. 판매자 Wallet 잔액 직접 증가
4. WalletHistory 기록 (SETTLEMENT_PAYOUT)
5. SettlementHistory 상태를 COMPLETED로 변경

### 4. 정산 실패 (FAILED)
1. 지갑 조회 실패 또는 예외 발생
2. SettlementHistory 상태를 FAILED로 변경
3. SettlementQueue 상태를 FAIL로 변경
4. retryCount 증가 (명시적 재시도 로직 미구현)

## 핵심 포인트
- **상태 관리 (SettlementQueue)**: READY → IN_PROGRESS → DONE/FAIL
- **상태 관리 (SettlementHistory)**: CREATED → COMPLETED/FAILED
- **이벤트 기반**: SettlementCreatedEvent 발행 → WalletSettlementService 수신
- **멱등성**: WalletHistory 중복 검증으로 중복 지급 방지
- **직접 잔액 증가**: 외부 이체 API 없음, Wallet 잔액 직접 증가
- **재시도**: retryCount만 증가, 명시적 재시도 로직 미구현
- **수수료 처리**: 정산 금액 계산 시 서비스 수수료 차감
- **이력 관리**: SettlementHistory와 WalletHistory에 기록
