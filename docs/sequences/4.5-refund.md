# 4.5 결제 취소 및 환불 - Sequence Diagram

## Diagram

```mermaid
sequenceDiagram
    actor User as 사용자
    participant Scheduler as 스케줄러
    participant RefundService as 환불 서비스
    participant FundingDB as 펀딩 DB
    participant PaymentDB as 결제 DB
    participant PaymentAPI as 결제 API
    participant NotificationService as 알림 서비스

    Note over FundingDB: 초기 상태<br/>펀딩 Status: EXPIRED
    Note over PaymentDB: 초기 상태<br/>결제 금액: 20,000원<br/>결제 상태: COMPLETED

    %% 환불 처리 로직 실행
    Scheduler->>+RefundService: 환불 처리 배치 작업 실행

    RefundService->>+FundingDB: EXPIRED 상태 펀딩 조회
    FundingDB-->>-RefundService: 실패한 펀딩 목록

    loop 각 실패한 펀딩에 대해
        RefundService->>+PaymentDB: 해당 펀딩의 결제 내역 조회
        PaymentDB-->>-RefundService: 결제 목록 반환<br/>(사용자, 20,000원)

        loop 각 결제 건에 대해
            RefundService->>+PaymentAPI: 환불 요청<br/>(결제 ID, 20,000원)

            PaymentAPI->>PaymentAPI: 결제 게이트웨이 환불 처리

            alt 환불 성공
                PaymentAPI-->>RefundService: 환불 성공 응답

                RefundService->>+PaymentDB: 결제 상태 변경<br/>(COMPLETED → REFUNDED)
                PaymentDB-->>-RefundService: 상태 변경 완료

                RefundService->>+NotificationService: 환불 완료 알림 요청
                NotificationService->>User: 환불 완료 알림 발송<br/>(20,000원 환불)
                deactivate NotificationService

            else 환불 실패
                PaymentAPI-->>RefundService: 환불 실패 응답

                RefundService->>RefundService: 재시도 큐에 등록

                RefundService->>+NotificationService: 환불 실패 알림 요청
                NotificationService->>User: 환불 실패 알림 발송
                deactivate NotificationService
            end

            deactivate PaymentAPI
        end
    end

    RefundService-->>-Scheduler: 환불 처리 완료

    Note over PaymentDB: 최종 상태<br/>결제 상태: REFUNDED<br/>환불 금액: 20,000원
    Note over User: 사용자 계좌에<br/>20,000원 입금 완료
```

## 주요 흐름

1. 스케줄러가 환불 처리 배치 작업 실행
2. EXPIRED 상태 펀딩 조회
3. 각 실패한 펀딩의 결제 내역 조회
4. 각 결제 건에 대해 환불 요청
5. 결제 게이트웨이를 통한 환불 처리
6. 환불 성공 시: 결제 상태를 REFUNDED로 변경하고 알림 발송
7. 환불 실패 시: 재시도 큐에 등록하고 실패 알림 발송
8. 환불 처리 완료

## 핵심 포인트
- **자동 환불**: 펀딩 실패 시 배치 작업을 통한 자동 환불
- **재시도 메커니즘**: 환불 실패 시 재시도 큐 활용
- **상태 관리**: 결제 상태를 REFUNDED로 명확히 변경
- **알림**: 성공/실패 모두 사용자에게 알림 발송
