## 4. @ComponentScan / @EntityScan / @EnableJpaRepositories 영향

### 4.1 현재 GiftifyApplication.java basePackages

```java
@ComponentScan(basePackages = {

    "domain",                // ← 비표준 (레거시 패키지)
    "payment",               // ← 비표준 (레거시)
```

### 4.2 레거시 패키지 5건 (R-NEW1 위험)

`domain`, `payment`, `wallet`, `walletHistory`, `giftify.support.web` 가 `app.giftify.*` 접두 없이 등록되어 있음. 이는 *과거 모듈 구조의 잔재* 로 추정됨. 평탄화 시 다음 확인 필요:

```bash
# 실제 해당 패키지에 클래스가 있는지
find . -type d -name "domain" -not -path "*/build/*" -not -path "*/app/giftify*"
find . -type d -name "payment" -not -path "*/build/*" -not -path "*/app/giftify*"
find . -type d -name "wallet" -not -path "*/build/*" -not -path "*/app/giftify*"
find . -type d -name "walletHistory" -not -path "*/build/*" -not -path "*/app/giftify*"
```

→ 빈 패키지면 *제거* + ApplicationContext 가 정상 시작하는지 검증.
→ 클래스 존재 시 → *해당 클래스의 패키지를 `app.giftify.*` 로 마이그레이션* 후 basePackages 정리.

### 5.2 원자적 vs 점진적 실행 권장

**점진적 권장** — 각 step 끝마다 `./gradlew compileJava` 통과 보장. 이유:
- 22 yml + 6 BC + 5 레거시 패키지 = 단일 commit 으로 묶으면 *bisect 불가*
- 사용자 cherry-pick 요구사항: 부분 적용 가능성 보존
- TDD 적합도 높음 (Modulith verify, ApplicationContext start, 단위 테스트)

각 step 단위 commit 예시:
- `refactor: support:common annotation 6건 → bc:shared 이동`
- `refactor: support:common validator 3건 → bc:shared 이동`
- `chore: GiftifyApplication 레거시 5 패키지 정리`
- `refactor: api-server 디렉터리 + build.gradle.kts 생성 (평탄화 1/N)`
- ... (각 BC 별 평탄화 commit)
